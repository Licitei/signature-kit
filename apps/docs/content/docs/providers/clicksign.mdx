---
title: Clicksign
description: "Crie solicitações de assinatura na Clicksign pela API v1, com o token em Redacted e falhas tipadas como SignatureKitError."
---

`@signature-kit/clicksign` cria na Clicksign o documento e os signatários, pela API v1, e notifica os signatários quando `send` não é `false`. O resultado é um `ClicksignSignatureRequestAttributes` com `id`, `state` e as URLs que a Clicksign devolver. Nenhum PDF é assinado no seu processo: a assinatura acontece na Clicksign.

## Instalação

```package-install
@signature-kit/http @signature-kit/clicksign
```

## Quando usar

Use a Clicksign quando o envio, os lembretes e a trilha de auditoria ficam na Clicksign. Se a aplicação precisa gerar os bytes assinados, use a [assinatura A1 de PDF](/docs/signing/pdf).

<Callout type="warn" title="Credenciais em Redacted">
  O token entra como `Redacted.make(...)` e só é aberto na chamada HTTP. Não passe tokens para componentes React nem
  para logs.
</Callout>

## Solicitação mínima

```ts title="clicksign.ts"
import * as Alchemy from "alchemy"
import { ClicksignSignatureRequest, providers as clicksignProviders } from "@signature-kit/clicksign"
import { signatureHttpClientLive } from "@signature-kit/http"
import { Effect, Layer, Redacted } from "effect"

export default class Contracts extends Alchemy.Stack<Contracts>()(
  "Contracts",
  {
    providers: Layer.merge(
      clicksignProviders({
        accessToken: Redacted.make(process.env.CLICKSIGN_TOKEN ?? ""),
        environment: "sandbox",
        locale: "pt-BR",
        autoClose: true,
      }),
      signatureHttpClientLive,
    ),
    state: Alchemy.inMemoryState(),
  },
  Effect.gen(function* () {
    return yield* ClicksignSignatureRequest("contrato-de-servico", {
      title: "Contrato de serviço",
      message: "Revise e assine este documento.",
      documents: [{ fileName: "contract.pdf", mimeType: "application/pdf", contentBase64: pdfBase64 }],
      recipients: [{ name: "Ana Silva", email: "ana@example.com", role: "signer" }],
      send: true,
    })
  }),
) {}
```

## Detalhes da integração

- `environment` aceita `"production"` ou `"sandbox"` (padrão). `baseUrl` substitui os dois.
- A API v1 da Clicksign exige o token no parâmetro `access_token` da URL. Nas mensagens de erro, esse valor aparece como `<redacted>`.
- Um documento por solicitação: `documents` é uma tupla de um item, e mais de um documento falha com `signature-kit.INVALID_INPUT`.
- `role` aceita `"signer"` ou `"approver"`; `routingOrder` define a ordem de assinatura.
- `locale` (`"pt-BR"`, padrão, ou `"en-US"`) e `autoClose` (padrão `true`) vão para o documento na Clicksign.

## Outras operações

`getClicksignSignatureRequest`, `listClicksignSignatureRequests`, `cancelClicksignSignatureRequest`, `deleteClicksignSignatureRequest` e `downloadClicksignSignedDocument` recebem as mesmas opções de `providers(...)` e exigem `SignatureHttpClient`. O download falha com `signature-kit.UNSUPPORTED_OPERATION` enquanto não houver arquivo assinado.

## Aguarde um estado final

`waitForClicksignSignatureRequest(options, id, pollInterval)` consulta a solicitação na hora e repete a cada `pollInterval` enquanto o estado for `draft` ou `sent`. O retorno traz o estado final (`completed`, `cancelled`, `deleted`, `declined` ou `expired`); confira `state` antes de baixar o documento. O intervalo precisa ser positivo e finito. Falhas de consulta não são repetidas automaticamente, e interromper o Effect cancela a consulta em andamento. O prazo máximo fica com a aplicação:

```ts title="wait.ts"
import { waitForClicksignSignatureRequest } from "@signature-kit/clicksign"
import type { ClicksignProviderOptions } from "@signature-kit/clicksign"
import { signatureHttpClientLive } from "@signature-kit/http"
import { Duration, Effect } from "effect"

declare const options: ClicksignProviderOptions
declare const requestId: string

const program = waitForClicksignSignatureRequest(options, requestId, Duration.seconds(2)).pipe(
  Effect.timeout(Duration.minutes(5)),
  Effect.provide(signatureHttpClientLive),
)
```

## Erros

Entrada inválida, falhas HTTP e respostas em formato inesperado falham como `SignatureKitError`, com `provider`, `operation` e o `status` HTTP quando disponíveis.
