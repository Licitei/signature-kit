---
title: Instalação
description: "Instale o runtime e o signer A1, configure a layer Signatures e adicione os pacotes de XML e PDF quando precisar."
---

Você vai instalar o runtime, carregar um certificado A1 e preparar a layer que os pacotes de formato consomem. Adicionar XML, PDF ou provedores depois não muda o contrato da sua aplicação.

<Steps>
  <Step title="Instale os pacotes">
    Comece pelo runtime `@signature-kit/signatures`, pelo signer `@signature-kit/a1` e pelo `effect`.

    ```package-install
    @signature-kit/signatures @signature-kit/a1 effect
    ```
  </Step>

  <Step title="Forneça a layer Signatures">
    O `a1SignaturesLayer` recebe os bytes do `.pfx` e a senha em `Redacted`, abre o PKCS#12 e fornece o serviço `Signatures`.

    ```ts title="signature-kit.ts"
    import { a1SignaturesLayer } from "@signature-kit/a1/signer"
    import { Redacted } from "effect"

    export const layer = a1SignaturesLayer({
      pfx,                                          // Uint8Array com os bytes do .pfx/.p12
      password: Redacted.make(process.env.A1_PASSWORD ?? ""),
    })
    ```

    <Callout type="info">
      A senha é um `Redacted.Redacted<string>`. Envolva-a com `Redacted.make(...)` para que o segredo não apareça em logs.
    </Callout>
  </Step>

  <Step title="Adicione XML e PDF">
    Os dois formatos usam a mesma layer. O XML também exige o `xmlRuntimeLayer`. O PDF exige a layer do motor `PdfCore`: `pdfCoreFileLayer` no Node e no Bun (com os serviços de arquivo de `@effect/platform-node`) ou `pdfCoreBrowserLayer` no navegador.

    ```package-install
    @signature-kit/xml @signature-kit/pdf @signature-kit/pdf-core @effect/platform-node
    ```

    O [primeiro uso](/docs/get-started/quickstart) mostra como assinar bytes, XML e PDF com essas layers.
  </Step>
</Steps>

## Erros que você pode encontrar

Toda falha chega como um `SignatureKitError` tipado no canal de erro. Os mais comuns ao carregar o certificado:

- [`signature-kit.WRONG_PASSWORD`](/docs/signing/errors#error-catalog): senha do certificado incorreta.
- [`signature-kit.NO_PRIVATE_KEY`](/docs/signing/errors#error-catalog): o arquivo não contém uma chave privada.
- [`signature-kit.INVALID_FORMAT`](/docs/signing/errors#error-catalog): o arquivo não é um certificado PKCS#12 (`.pfx`/`.p12`).
