---
title: XML-DSig
description: "Assine XML com signXml e verifique com verifyXml: referência enveloped, certificado X.509 no KeyInfo e chave de verificação explícita."
---

`signXml` assina uma string XML usando o serviço `Signatures`. `verifyXml` confere a assinatura sem precisar de `Signatures`, mas exige que você informe a chave ou o certificado confiável.

<Steps>
  <Step title="Instale o pacote">
    O formato XML fica em `@signature-kit/xml` e usa o serviço `Signatures` fornecido por um adapter de assinatura.

    ```package-install
    @signature-kit/xml
    ```
  </Step>

  <Step title="Assine um documento XML">
    `signXml` recebe um `XmlSigningRequest` e retorna `Effect<string, XmlError | SignatureKitError, Signatures | XmlRuntime>` com o XML assinado. Forneça `Signatures` com `a1SignaturesLayer(...)` e o `XmlRuntime` com `xmlRuntimeLayer`.

    ```ts title="sign-xml.ts"
    import { signXml } from "@signature-kit/xml/sign"
    import { xmlRuntimeLayer } from "@signature-kit/xml/runtime"
    import { a1SignaturesLayer } from "@signature-kit/a1/signer"
    import { Effect, Redacted } from "effect"

    const layer = a1SignaturesLayer({
      pfx,                                       // Uint8Array — bytes do .pfx/.p12
      password: Redacted.make(process.env.A1_PASSWORD ?? ""),
    })

    // signXml -> Effect<string, XmlError | SignatureKitError, Signatures | XmlRuntime>
    const signed: string = yield* signXml({
      xml,                                       // string — documento de entrada
      referenceId: "nfe-1",
    }).pipe(Effect.provide(layer), Effect.provide(xmlRuntimeLayer))
    // `signed` é o XML com o <Signature> embutido
    ```
  </Step>

  <Step title="Referência e opções">
    `referenceId` define o alvo da assinatura enveloped: `referenceId: "nfe-1"` gera uma `Reference` com URI `"#nfe-1"`, que aponta para o elemento com esse `Id` no próprio documento. Só `xml` é obrigatório:

    ```ts title="request-xml.ts"
    const signed = yield* signXml({
      xml,
      algorithm: "rsa-sha256",          // padrão; ou "rsa-sha512", ou o legado "rsa-sha1"
      referenceId: "nfe-1",             // -> Reference URI "#nfe-1"
      signatureId: "SignatureKit-NFe",  // Id do elemento <Signature>
      canonicalization: "exclusive",    // padrão; ou "inclusive"
    }).pipe(Effect.provide(layer), Effect.provide(xmlRuntimeLayer))
    ```

    Sem `algorithm`, vale `"rsa-sha256"`. O certificado X.509 do signatário vai no `KeyInfo` da assinatura, mas `verifyXml` não confia nele automaticamente; os dois últimos passos mostram como informar a chave ou o certificado confiável.
  </Step>

  <Step title="Estrutura da NF-e">
    Na NF-e, o `Id` de `infNFe` é a chave de acesso, e a assinatura aponta para ele. Use esse valor como `referenceId` para que a URI fique `"#NFe35..."`.

    ```ts title="sign-nfe.ts"
    const xml = `<NFe xmlns="http://www.portalfiscal.inf.br/nfe">
      <infNFe Id="NFe35200114200166000187550010000000071234567890" versao="4.00">
        <!-- ide, emit, dest, det, total, transp, ... -->
      </infNFe>
    </NFe>`

    const signed = yield* signXml({
      xml,
      referenceId: "NFe35200114200166000187550010000000071234567890",
    }).pipe(Effect.provide(layer), Effect.provide(xmlRuntimeLayer))
    // o <Signature> entra como irmão de <infNFe>, apontando para "#NFe35..."
    ```

    <Callout type="info">
      `signXml` retorna o XML assinado como `string`, pronto para o envio à SEFAZ.
    </Callout>
  </Step>

  <Step title="Verifique a assinatura">
    `verifyXml` recebe um `XmlVerificationRequest` e retorna `Effect<XmlVerificationResult, XmlError, XmlRuntime>`. Não exige `Signatures`, mas exige o `XmlRuntime`. Informe exatamente um entre `trustedCertificateDer` (o certificado X.509 em que você confia) e `publicKeyDer` (o `SubjectPublicKeyInfo` em DER).

    Quando a aplicação lê um elemento assinado específico, use `requiredReference`. O `path` vai do elemento raiz até o alvo; cada segmento precisa corresponder a exatamente um filho direto, com namespace. Use `namespaceUri: null` para elementos sem namespace.

    <Callout type="warn">
      `verifyXml` nunca confia no certificado embutido no `KeyInfo`. Se confiasse, qualquer pessoa poderia alterar o
      documento, assiná-lo com a própria chave e incluir o próprio certificado. Omitir a fonte de confiança ou informar
      as duas falha com `xml.INVALID_INPUT`.
    </Callout>

    ```ts title="verify-xml.ts"
    import { verifyXml } from "@signature-kit/xml/verify"
    import { xmlRuntimeLayer } from "@signature-kit/xml/runtime"
    import { Effect } from "effect"

    // verifyXml -> Effect<XmlVerificationResult, XmlError, XmlRuntime>
    const result = yield* verifyXml({
      xml: signed,
      trustedCertificateDer,                     // Uint8Array — certificado X.509 (DER) obtido por outro canal
      requiredReference: {
        uri: "#nfe-1",
        path: [
          { localName: "NFe", namespaceUri: "http://www.portalfiscal.inf.br/nfe" },
          { localName: "infNFe", namespaceUri: "http://www.portalfiscal.inf.br/nfe" },
        ],
      },
    }).pipe(Effect.provide(xmlRuntimeLayer))

    result.valid           // boolean
    result.signatureCount  // number — elementos <Signature> encontrados
    result.referenceUris   // readonly string[] — por exemplo ["#nfe-1"]
    ```

    ### Limites de verificação

    Para limitar o custo da verificação, o documento pode ter no máximo 4 elementos `<Signature>`, 4 `<Reference>` diretos de `SignedInfo` por assinatura, 8 referências no total, 3 `<Transform>` diretos por referência e 8 transformações no total. Cada referência aceita uma única transformação de canonicalização. Passar de um limite resulta em `result.valid === false`, antes da verificação criptográfica.

    Só XML 1.0 é aceito. O parser rejeita entradas com mais de 10 MiB, 16.384 nós, 2.048 atributos, 64 declarações de namespace ou profundidade 1.024. Valores de `PrefixList` em `InclusiveNamespaces` têm limite de 4.096 caracteres e 64 tokens.

    O documento deve ter exatamente um elemento raiz. Antes e depois dele, só são aceitos a declaração XML inicial e espaços em branco.

    `signXml` aplica as mesmas regras ao XML que produz e falha com `xml.SIGN_FAILED` em vez de retornar um documento que `verifyXml` rejeitaria.
  </Step>

  <Step title="Verificação com chave explícita">
    Quando você tem só a chave pública (`SubjectPublicKeyInfo`) em vez do certificado completo, passe `publicKeyDer`.

    ```ts title="verify-key.ts"
    import { verifyXml } from "@signature-kit/xml/verify"
    import { xmlRuntimeLayer } from "@signature-kit/xml/runtime"
    import { Effect } from "effect"

    const result = yield* verifyXml({
      xml: signed,
      publicKeyDer,                              // Uint8Array — SubjectPublicKeyInfo em DER
      requiredReference: {
        uri: "#nfe-1",
        path: [
          { localName: "NFe", namespaceUri: "http://www.portalfiscal.inf.br/nfe" },
          { localName: "infNFe", namespaceUri: "http://www.portalfiscal.inf.br/nfe" },
        ],
      },
    }).pipe(Effect.provide(xmlRuntimeLayer))
    // result.valid: boolean
    ```
  </Step>
</Steps>

## Erros mais comuns

Falhas do A1 chegam como `SignatureKitError`. Falhas de leitura, canonicalização, assinatura e verificação de XML chegam como `XmlError`.

<Cards>
  <Card title="xml.INVALID_INPUT" href="/docs/signing/errors#format-errors">Requisição de assinatura ou verificação inválida, incluindo fonte de confiança ausente ou duplicada.</Card>
  <Card title="xml.INVALID_XML" href="/docs/signing/errors#format-errors">A string não é um XML válido ou viola os limites do parser.</Card>
  <Card title="xml.SIGN_FAILED" href="/docs/signing/errors#format-errors">A assinatura não pôde ser concluída, por exemplo quando nenhum elemento tem o Id de referenceId.</Card>
</Cards>

<Callout type="info">
  Assinatura inválida, `requiredReference` que não corresponde ao documento e limite de verificação excedido **não**
  são erros do Effect: `verifyXml` termina com sucesso e retorna `result.valid === false`. O canal de erro só recebe
  os casos abaixo.
</Callout>

<Cards>
  <Card title="xml.VERIFY_FAILED" href="/docs/signing/errors#format-errors">A verificação em si não pôde ser concluída.</Card>
  <Card title="xml.SIGNATURE_NOT_FOUND" href="/docs/signing/errors#format-errors">O documento não tem nenhum elemento `<Signature>`.</Card>
  <Card title="xml.KEY_IMPORT_FAILED" href="/docs/signing/errors#format-errors">Não foi possível importar `publicKeyDer` ou `trustedCertificateDer` como chave de verificação.</Card>
</Cards>
