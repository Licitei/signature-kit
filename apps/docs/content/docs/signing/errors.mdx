description: "As falhas do SignatureKit ficam no canal de erro do Effect como SignatureKitError, PdfError ou XmlError. Trate pelo code com catchTag."
---

O SignatureKit não lança exceções. As falhas do núcleo, do adapter A1 e das APIs de provedores chegam no canal de erro do `Effect` como `SignatureKitError`; os formatos acrescentam `PdfError` e `XmlError`. O tipo de retorno declara o erro (`Effect<SignatureArtifact, SignatureKitError>`), então o compilador acompanha o que você tratou e o que continua se propagando.

## O formato do erro

`SignatureKitError` é uma classe com `_tag` igual a `"SignatureKitError"`. Campos:

- `code`: um dos 21 literais `"signature-kit.*"` do [catálogo](#error-catalog).
- `retryable`: booleano definido **no ponto da falha**, não por código. O mesmo `code` pode chegar com `retryable: true` em uma chamada e `false` em outra.
- `reason?`: mensagem de contexto para logs e telemetria. O texto de interface deve vir do `code`, nunca deste campo.
- `operation?`: a operação que falhou, no formato `dominio.acao` (por exemplo `pkcs12.parse` ou `http.request`).
- `schemaName?`: o schema que falhou na decodificação, quando a falha veio de `Schema.decodeUnknownEffect`.
- `issueMessage?`: o texto do problema de decodificação (`String(issue)`).
- `provider?`: o provedor remoto (Clicksign, Assinafy, ZapSign, DocuSeal ou Documenso), em falhas das APIs de provedores.
- `status?`: o status HTTP da resposta do provedor.
- `retryAfterEpochSeconds?`: quando tentar de novo, em segundos Unix, se o provedor informou (por exemplo, em limite de requisições).
- `get message()`: a mensagem padrão em inglês do code, ou `reason` nos codes marcados como _editável_ no catálogo.

```ts title="error-shape.ts"
import type { Effect } from "effect"
import type { SignatureArtifact, SignatureKitError, SignatureKitErrorCode } from "@signature-kit/signatures"

declare const sign: Effect.Effect<SignatureArtifact, SignatureKitError>

// _tag: "SignatureKitError"
class SignatureKitError {
  readonly code: SignatureKitErrorCode   // 21 literais "signature-kit.*"
  readonly retryable: boolean            // definido no ponto da falha
  readonly reason?: string               // contexto para logs
  readonly operation?: string
  readonly schemaName?: string
  readonly issueMessage?: string
  readonly provider?: string
  readonly status?: number
  readonly retryAfterEpochSeconds?: number
  get message(): string                  // padrão do code, ou reason nos codes editáveis
}
```

<Callout type="info">
  Não trate `retryable` como propriedade do code. Leia sempre `error.retryable` do valor recebido: só o ponto da falha
  sabe se vale tentar de novo.
</Callout>

## Tratamento por code

Todas as falhas têm a mesma tag, então `Effect.catchTag("SignatureKitError", ...)` captura o erro e você decide pelo `error.code`. Um `switch` sobre `code` sem `default` pode ser checado como exaustivo pelo compilador.

```ts title="handle-error.ts"
import { Effect } from "effect"
import { a1SignaturesLayer } from "@signature-kit/a1/signer"
import { signatures } from "@signature-kit/signatures"

const program = Effect.gen(function* () {
  return yield* signatures.sign({ content, algorithm: "rsa-sha256" })
}).pipe(Effect.provide(a1SignaturesLayer({ pfx, password })))

const handled = program.pipe(
  Effect.catchTag("SignatureKitError", (error) => {
    switch (error.code) {
      case "signature-kit.WRONG_PASSWORD":
        return Effect.fail("Senha do certificado incorreta. Peça a senha de novo.")
      case "signature-kit.SIGN_FAILED":
        // retryable vem do ponto da falha, não do code.
        return error.retryable ? program : Effect.fail(error.message)
      default:
        return Effect.fail(error.message)
    }
  }),
)
```

Para tratar só uma falha específica e deixar as outras seguirem, use `Effect.catchIf` com um predicado sobre `_tag` e `code`:

```ts title="catch-if.ts"
import { Effect } from "effect"
import type { SignatureKitError } from "@signature-kit/signatures"

const recovered = program.pipe(
  Effect.catchIf(
    (error): error is SignatureKitError =>
      error._tag === "SignatureKitError" && error.code === "signature-kit.WRONG_PASSWORD",
    (error) =>
      Effect.logWarning(`signing aborted at ${error.operation ?? "sign"}: ${error.message}`),
  ),
)
```

<Callout type="info">
  Em rotinas de nova tentativa, decida por `error.code` e `error.retryable` juntos. Por exemplo, repita um
  [`signature-kit.SIGN_FAILED`](#error-catalog) só quando `error.retryable` for `true`.
</Callout>

## Catálogo de erros [#error-catalog]

Os 21 codes de `SignatureKitError` e suas mensagens padrão. Nos codes marcados como _editável_, `message` retorna `reason` quando ele existe. Cada linha tem uma âncora `#err-<CODE>` (por exemplo [`#err-WRONG_PASSWORD`](#err-WRONG_PASSWORD)) para links diretos.

## Mensagens localizadas

Não monte o texto de interface comparando trechos de `reason`. Esse texto é diagnóstico e pode mudar a qualquer versão:

```ts title="nao-inspecione-reason.ts"
// Não faça isso.
export function getCertificateErrorMessage(error: { reason?: string }) {
  const reason = error.reason ?? ""
  if (reason.includes("not valid on the current date")) return "Certificado expirado"
  if (reason.includes("Brazilian CPF or CNPJ")) {
    return "Certificado não contém CPF ou CNPJ brasileiro"
  }

  return "Arquivo de certificado inválido"
}
```

Use `@signature-kit/i18n` na borda da aplicação. Passe os catálogos dos erros que aquele trecho pode receber. `errorMessage` lê `_tag` e `code` do valor e, se a locale pedida não tiver a mensagem, usa o inglês:

```ts title="mensagem-de-erro-localizada.ts"
import { errorMessage } from "@signature-kit/i18n"
import { signatureKitErrorMessages } from "@signature-kit/signatures"
import { pdfErrorMessages } from "@signature-kit/pdf/config"

const message = errorMessage(error, {
  locale: "pt-BR",
  catalogs: [signatureKitErrorMessages, pdfErrorMessages],
  overrides: {
    "pt-BR": {
      "signature-kit.WRONG_PASSWORD": "Senha do certificado incorreta",
    },
  },
})
```

## Erros de formato e de provedor [#format-errors]

Os módulos de formato acrescentam suas próprias classes de erro. As APIs de provedores não: entrada inválida, falha HTTP, resposta em formato inesperado e operação não suportada continuam como `SignatureKitError`.

<Cards>
  <Card title="XmlError">Codes `xml.*`. `signXml` falha com `XmlError | SignatureKitError`; `verifyXml`, só com `XmlError`. O catálogo de mensagens é `xmlErrorMessages`, em `@signature-kit/xml/config`.</Card>
  <Card title="PdfError">Codes `pdf.*`. `signPdf` falha com `PdfError | CmsError | SignatureKitError`. Por exemplo, `hashAlgorithm: "sha384"` falha como `pdf.SIGN_FAILED`, porque não existe `rsa-sha384` no adapter. O catálogo é `pdfErrorMessages`, em `@signature-kit/pdf/config`.</Card>
  <Card title="APIs de provedores">Sem classe própria. As falhas são `SignatureKitError` com `provider`, `operation`, `schemaName` e `status` quando esses dados existem.</Card>
</Cards>

```ts title="families.ts"
import { Effect } from "effect"
import { signXml } from "@signature-kit/xml/sign"
import { xmlRuntimeLayer } from "@signature-kit/xml/runtime"
import { signPdf } from "@signature-kit/pdf/sign"
import type { PdfCore } from "@signature-kit/pdf-core/pdf-core"
import type { Layer } from "effect"
import { a1SignaturesLayer } from "@signature-kit/a1/signer"

declare const pdfCoreLayer: Layer.Layer<PdfCore>
const layer = a1SignaturesLayer({ pfx, password })

// signXml -> XmlError | SignatureKitError
const xml = signXml({ xml: source, referenceId: "nfe-1" }).pipe(
  Effect.provide(layer),
  Effect.provide(xmlRuntimeLayer),
  Effect.catchTags({
    XmlError: (error) => Effect.fail(`XML: ${error.code}`),
    SignatureKitError: (error) => Effect.fail(`Assinatura: ${error.code}`),
  }),
)

// signPdf -> PdfError | CmsError | SignatureKitError
const pdf = signPdf({ pdf: bytes, policy: "pades-icp-brasil" }).pipe(
  Effect.provide(layer),
  Effect.provide(pdfCoreLayer),
  Effect.catchTag("PdfError", (error) => Effect.fail(`PDF: ${error.code}`)),
)
```

Nas funções dos provedores, trate pelo `error.code` da mesma forma:

```ts title="remote-signer-error.ts"
import { Effect } from "effect"
import { getClicksignSignatureRequest } from "@signature-kit/clicksign"
import type { ClicksignProviderOptions } from "@signature-kit/clicksign"
import { signatureHttpClientLive } from "@signature-kit/http"

declare const options: ClicksignProviderOptions
declare const requestId: string

const request = getClicksignSignatureRequest(options, requestId).pipe(
  Effect.provide(signatureHttpClientLive),
  Effect.catchTag("SignatureKitError", (error) => {
    switch (error.code) {
      case "signature-kit.HTTP":
        return Effect.fail(`HTTP ${error.status ?? "?"} em ${error.provider ?? "provedor"}`)
      case "signature-kit.RESPONSE_SHAPE":
        return Effect.fail("O provedor respondeu em um formato inesperado.")
      default:
        return Effect.fail(error.message)
    }
  }),
)
```

Formatos e provedores são pacotes separados. Instale só o que você usa:

```package-install
@signature-kit/xml @signature-kit/pdf @signature-kit/http @signature-kit/clicksign
```
