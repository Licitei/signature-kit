`signPdf` assina os bytes de um PDF com a política `"pades-ades"` ou `"pades-icp-brasil"` (AD-RB), e `verifyPdf` confere o resultado. A assinatura em si vem do serviço `Signatures`, fornecido por `a1SignaturesLayer`; o módulo de PDF só altera o documento.

## Instalação

```package-install
@signature-kit/pdf
```

<Callout type="info">
  `signPdf` exige os serviços `Signatures` e `PdfCore`; `verifyPdf` exige só o `PdfCore`. Forneça `pdfCoreFileLayer`
  no Node e no Bun (com a layer da plataforma) ou `pdfCoreBrowserLayer` no navegador.
</Callout>

## Assine um PDF

`signPdf(input: PdfSigningRequest)` retorna `Effect<Uint8Array, PdfError | CmsError | SignatureKitError, Signatures | PdfCore>` com os bytes do PDF assinado. A assinatura é gravada como atualização incremental: os bytes originais, e qualquer assinatura anterior, ficam intactos.

```ts title="pdf-core-layer.ts"
import * as NodeServices from "@effect/platform-node/NodeServices"
import { pdfCoreFileLayer } from "@signature-kit/pdf-core/file"
import { Layer } from "effect"

export const pdfCoreLayer = pdfCoreFileLayer.pipe(Layer.provide(NodeServices.layer))
```

```ts title="sign-pdf.ts"
import { signPdf } from "@signature-kit/pdf/sign"
import { a1SignaturesLayer } from "@signature-kit/a1/signer"
import { Effect, Redacted } from "effect"
import { pdfCoreLayer } from "./pdf-core-layer"

const program = signPdf({
  pdf,                          // Uint8Array — PDF original
  reason: "Aprovação do contrato",
  name: "Maria Souza",
  location: "São Paulo, SP",
  signatureLength: 16384,       // bytes reservados para o CMS em /Contents
}).pipe(
  Effect.provide(
    a1SignaturesLayer({
      pfx,                                   // Uint8Array — PKCS#12 (.pfx/.p12)
      password: Redacted.make(process.env.A1_PASSWORD ?? ""),
    }),
  ),
  Effect.provide(pdfCoreLayer),
)

const signedPdf = await Effect.runPromise(program)  // política "pades-ades"
```

`signatureLength` define quantos bytes ficam reservados em `/Contents` para o CMS. O padrão é 16384 (32768 na política ICP-Brasil); se o CMS não couber, a assinatura falha com `pdf.SIGNATURE_TOO_LARGE`. `reason` e `name` têm como padrão `"Digital signature"` e `"SignatureKit signer"`. Os demais campos opcionais são `contactInfo`, `location`, `signingTime`, `hashAlgorithm`, `policy`, `icpBrasil`, `timestamp` e `appearance`.

<Callout type="warn">
  `hashAlgorithm` aceita `"sha256"` (padrão, vira `rsa-sha256`), `"sha512"` (`rsa-sha512`) e o legado `"sha1"`
  (`rsa-sha1`). `"sha384"` falha com `pdf.SIGN_FAILED`, porque o adapter de assinatura não tem `rsa-sha384`.
</Callout>

## Duas assinaturas no mesmo PDF

`Signatures` é um requisito do Effect, então cada chamada escolhe o certificado. Para que duas pessoas assinem o mesmo documento, assine o resultado da primeira assinatura com o segundo A1. Como cada assinatura é uma atualização incremental, a primeira continua válida.

```ts title="two-a1-signers.ts"
import { signPdf } from "@signature-kit/pdf/sign"
import { a1SignaturesLayer } from "@signature-kit/a1/signer"
import { Effect, Redacted } from "effect"
import { pdfCoreLayer } from "./pdf-core-layer"

const program = Effect.gen(function* () {
  const signedByMaria = yield* signPdf({
    pdf: unsignedPdf,
    reason: "Maria aprovou o contrato",
    name: "Maria Souza",
  }).pipe(
    Effect.provide(a1SignaturesLayer({ pfx: mariaPfx, password: Redacted.make(mariaPassword) })),
  )

  return yield* signPdf({
    pdf: signedByMaria,
    reason: "João aprovou o contrato",
    name: "João Silva",
  }).pipe(
    Effect.provide(a1SignaturesLayer({ pfx: joaoPfx, password: Redacted.make(joaoPassword) })),
  )
}).pipe(Effect.provide(pdfCoreLayer))

const signedByBoth = await Effect.runPromise(program)
```

Nenhum segredo ou estado global é compartilhado entre os dois certificados. `verifyPdfSignatures` retorna as duas assinaturas, em ordem de revisão.

## Posicione uma assinatura visível

Sem `appearance`, a assinatura é invisível. Com `appearance.placement.kind: "auto"`, o pacote calcula um retângulo na página escolhida a partir da âncora, sem sobrepor widgets e anotações existentes.

```ts title="position-pdf-signature.ts"
const signed = await Effect.runPromise(
  signPdf({
    pdf,
    appearance: {
      placement: {
        kind: "auto",
        page: "last",          // ou pageIndex para uma página exata
        anchor: "bottom-right",
        width: 180,
        height: 54,
        margin: 36,
        gap: 8,                // distância mínima de widgets e anotações
      },
    },
  }).pipe(Effect.provide(layer)),
)

// Manual: coordenadas PDF [esquerda, base, direita, topo]
const manual = { appearance: { placement: { kind: "manual", pageIndex: 0, widgetRect: [72, 72, 216, 108] } } }

// Invisível: campo /Widget sem área visível
const invisible = { appearance: { placement: { kind: "invisible" } } }
```

Use `kind: "manual"` quando a aplicação já tem coordenadas confiáveis e `kind: "invisible"` quando o PDF deve levar só a assinatura criptográfica. Se o modo automático não encontrar espaço dentro das margens, o Effect falha com `pdf.SIGNATURE_PLACEMENT_FAILED`.

## Política PAdES ICP-Brasil

`PdfSignaturePolicy` tem dois valores: `"pades-ades"` (padrão) e `"pades-icp-brasil"`. A primeira grava `/SubFilter /adbe.pkcs7.detached`; a segunda grava `/ETSI.CAdES.detached` e, se você não passar `icpBrasil`, embute os metadados da política PA_PAdES_AD_RB_v1_1 que vêm fixos em `@signature-kit/cms`. Nada é baixado em tempo de execução.

```ts title="icp-brasil-policy.ts"
const signed = signPdf({
  pdf,
  policy: "pades-icp-brasil",
}).pipe(Effect.provide(layer))

// icpBrasil explícito substitui a política AD-RB embutida.
const explicit = signPdf({
  pdf,
  policy: "pades-icp-brasil",
  hashAlgorithm: "sha256",
  signatureLength: 49152,
  icpBrasil: customPolicy,
}).pipe(Effect.provide(layer))
```

A política AD-RB embutida traz `policyOid`, `policyHash`, `policyHashAlgorithm` e `policyUri` da PA_PAdES_AD_RB_v1_1.

<Callout type="info">
  Ao passar um `icpBrasil` próprio, use o mesmo algoritmo em `policyHashAlgorithm` e em `hashAlgorithm`: `"sha256"`
  ou `"sha512"`.
</Callout>

## Verifique com verifyPdf

`verifyPdf(input: PdfVerificationRequest)` retorna `Effect<PdfVerificationResult, PdfError | CmsError, PdfCore>`, **sem** exigir `Signatures`. Passe `trustedRoots` (uma lista de `Uint8Array` em DER) para validar a cadeia contra as suas raízes.

```ts title="verify-pdf.ts"
import { verifyPdf } from "@signature-kit/pdf/verify"
import { Effect } from "effect"
import { pdfCoreLayer } from "./pdf-core-layer"

const result = await Effect.runPromise(
  verifyPdf({ pdf: signedPdf, trustedRoots }).pipe(Effect.provide(pdfCoreLayer)),
)

result.valid              // boolean — todas as assinaturas válidas
result.chainValid         // boolean — cadeia de todas as assinaturas válida
result.revocationStatus   // "checked" | "not_checked"
result.signatureCount     // number — assinaturas encontradas
result.byteRange          // [number, number, number, number] — da assinatura mais recente
result.signerSerialNumber // string | null — da assinatura mais recente
```

`valid` exige integridade criptográfica e cobertura correta do arquivo em todas as assinaturas; com `trustedRoots`, exige também a cadeia válida. `not_checked` significa que a revogação não foi consultada. Um PDF sem assinatura (sem `/ByteRange`) falha com `pdf.PLACEHOLDER_NOT_FOUND`.

### Uma assinatura por vez

`verifyPdfSignatures` retorna uma entrada por assinatura, em ordem de revisão, com número de série do signatário, validade criptográfica, cobertura da revisão, validade da cadeia, estado de revogação, byte range e fim da revisão. Uma assinatura anterior continua válida com `coversFileEnd: false` depois que outras são adicionadas. `verifyPdf` usa a mesma implementação e agrega o resultado.

```ts title="verify-each.ts"
import { verifyPdfSignatures } from "@signature-kit/pdf/verify"

declare const pdf: Uint8Array
declare const trustedRoots: Uint8Array[]

const verification = verifyPdfSignatures({ pdf, trustedRoots })
```

## Carimbo com a sua marca

`PdfSignatureBadge` aceita `logoPng`, `signaturePng`, cabeçalho, linhas, rodapé, QR code e cores. As imagens mantêm a proporção; logo e QR ficam em uma coluna separada da assinatura manuscrita. Os PNGs são validados antes de entrar no PDF (até 16 MB e 16 megapixels). Um carimbo sem área útil dentro do espaçamento interno falha com `pdf.STAMP_FAILED`.

```ts title="stamp-badge.ts"
import type { PdfSignatureBadge } from "@signature-kit/pdf/config"
import { stampPdfVisibleSignature } from "@signature-kit/pdf/stamp"

const badge = {
  logoPng,
  signaturePng,
  header: { text: "ACME" },
  rows: [[{ label: "Signatário", value: "João Silva" }]],
  footer: [{ text: "Contrato assinado digitalmente" }],
  qr: { text: "https://example.com/verify" },
  theme: { borderColor: "#1D4ED8", headerColor: "#1D4ED8" },
} satisfies PdfSignatureBadge

// Effect<Uint8Array, PdfError, PdfCore>
const stamped = stampPdfVisibleSignature({
  pdf,
  pageIndex: 0,
  rect: { pageIndex: 0, x: 24, y: 24, width: 320, height: 128 },
  badge,
})
```

## Juntar PDFs

`mergePdfs([first, second])` copia as páginas para um novo PDF. Campos de formulário (AcroForm), metadados do documento e estado de formulário das origens **não** são mantidos; use para conteúdo já achatado. PDFs assinados são recusados com `pdf.INVALID_BUILDER_INPUT`, a menos que você passe `{ signedSources: "flatten" }`, o que descarta as assinaturas.

## Erros mais comuns

Assinatura e verificação de PDF falham com códigos `pdf.*` (`PdfError`). Erros do A1 que fornece `Signatures` chegam como `signature-kit.*`.

- [`pdf.SIGN_FAILED`](/docs/signing/errors#format-errors): `hashAlgorithm` não suportado (`"sha384"`).
- [`pdf.SIGNATURE_TOO_LARGE`](/docs/signing/errors#format-errors): o CMS não coube no espaço reservado; aumente `signatureLength`.
- [`pdf.SIGNATURE_PLACEMENT_FAILED`](/docs/signing/errors#format-errors): o posicionamento automático não encontrou espaço ou recebeu dimensões inválidas.
- [`pdf.INVALID_PDF`](/docs/signing/errors#format-errors): os bytes não formam um PDF válido.
- [`pdf.PLACEHOLDER_NOT_FOUND`](/docs/signing/errors#format-errors): `verifyPdf` não encontrou `/ByteRange`, por exemplo em um PDF sem assinatura.
- [`signature-kit.WRONG_PASSWORD`](/docs/signing/errors#error-catalog): a senha do A1 está errada.
