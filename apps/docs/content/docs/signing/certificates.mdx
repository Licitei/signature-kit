---
title: Certificados A1
description: "Leia a identidade do titular de um A1 (e-CPF ou e-CNPJ), inspecione o certificado completo e confira a validade e os campos ICP-Brasil."
---

Um certificado A1 é um arquivo PKCS#12 (`.pfx`/`.p12`) carregado pelo `@signature-kit/a1`. Depois de carregado, o serviço `Signatures` oferece duas leituras: a identidade resumida do titular e o certificado completo.

<Steps>
  <Step title="Leia a identidade">
    ### Leia a identidade

    `signatures.inspect()` retorna um `Effect<SignerIdentity, SignatureKitError, Signatures>` com o essencial do titular: subject, emissor, número de série, thumbprint, período de validade e o `document` opcional. Forneça uma layer de `Signatures` (aqui, `a1SignaturesLayer`) para que a chamada encontre o certificado carregado.

    ```ts title="read-identity.ts"
    import { a1SignaturesLayer } from "@signature-kit/a1/signer"
    import { signatures } from "@signature-kit/signatures"
    import { Effect, Redacted } from "effect"

    const layer = a1SignaturesLayer({
      pfx,                                          // Uint8Array — bytes do .pfx/.p12
      password: Redacted.make(process.env.A1_PASSWORD ?? ""),
    })

    export const readIdentity = Effect.gen(function* () {
      const identity = yield* signatures.inspect()

      console.log(identity.subject)       // titular do certificado
      console.log(identity.issuer)        // AC emissora
      console.log(identity.serialNumber)  // número de série
      console.log(identity.thumbprint)    // SHA-256 do certificado
      console.log(identity.validFrom, identity.validTo)

      // CNPJ quando existir; senão, CPF; ausente se nenhum for encontrado
      if (identity.document !== undefined) {
        console.log("document:", identity.document)
      }
    }).pipe(Effect.provide(layer))
    ```

    <Callout type="info">
      `document` só é preenchido quando o certificado traz CPF ou CNPJ nos campos ICP-Brasil. Se houver os dois (caso
      comum no e-CNPJ, que também carrega o CPF do responsável), vale o CNPJ. Teste sempre `!== undefined`.
    </Callout>
  </Step>

  <Step title="O tipo SignerIdentity">
    ### O tipo SignerIdentity

    O formato exato do retorno de `inspect`. `validFrom` e `validTo` são `Date`; `document` é o único campo opcional.

    ```ts title="signer-identity.ts"
    // retorno de signatures.inspect()
    type SignerIdentity = {
      subject: string
      issuer: string
      serialNumber: string
      thumbprint: string
      validFrom: Date
      validTo: Date
      document?: string   // CNPJ ou CPF, só dígitos
    }
    ```
  </Step>

  <Step title="Inspecione o certificado">
    ### Inspecione o certificado

    Quando a identidade não basta, `signatures.certificate()` retorna um `Effect<Certificate, SignatureKitError, Signatures>` com o certificado inteiro: PEM, DER, chave pública, a flag `isValid`, o SubjectAltName e o bloco `brazilian` com CPF e CNPJ.

    <Callout type="warn" title="A chave privada é Redacted">
      `privateKeyPem` é um `Redacted<string>` e não aparece em logs, `console.log` nem `JSON.stringify`. Chame
      `Redacted.value(...)` apenas no ponto em que a chave é usada.
    </Callout>

    ```ts title="inspect.ts"
    import { signatures } from "@signature-kit/signatures"
    import { Effect, Redacted } from "effect"

    // forneça o mesmo a1SignaturesLayer({ pfx, password }) do passo anterior
    export const inspectCertificate = Effect.gen(function* () {
      const cert = yield* signatures.certificate()

      console.log(cert.isValid)        // data atual dentro do período de validade
      console.log(cert.fingerprint)    // SHA-256 em hexadecimal
      console.log(cert.subjectAltName) // string | null
      console.log(cert.brazilian)      // { cnpj, cpf }

      const pem = Redacted.value(cert.privateKeyPem) // só no ponto de uso
    }).pipe(Effect.provide(layer))
    ```

    `isValid` é calculado uma vez, quando o arquivo é lido, e só compara a data atual com o período de validade. Não indica confiança na cadeia nem situação de revogação.
  </Step>

  <Step title="O tipo Certificate">
    ### O tipo Certificate

    O formato completo do retorno de `signatures.certificate()`. O certificado aparece em três codificações (`certPem`, `certificateDer`, `publicKeyDer`), e a chave privada fica em `Redacted`.

    ```ts title="certificate.ts"
    // retorno de signatures.certificate()
    type Certificate = {
      serialNumber: string
      subject: {
        commonName: string | null
        organization: string | null
        organizationalUnit: string | null
        country: string | null
        state: string | null
        locality: string | null
        raw: string
      }
      issuer: {
        commonName: string | null
        organization: string | null
        country: string | null
        raw: string
      }
      validity: { notBefore: Date; notAfter: Date }
      fingerprint: string
      subjectAltName: string | null
      isValid: boolean
      brazilian: { cnpj: string | null; cpf: string | null }
      certPem: string
      certificateDer: Uint8Array
      intermediateCertificates: readonly Uint8Array[]   // ACs intermediárias do .pfx; signPdf as inclui no CMS
      publicKeyDer: Uint8Array
      privateKeyPem: Redacted<string>
    }
    ```
  </Step>

  <Step title="Validade e ICP-Brasil">
    ### Validade e ICP-Brasil

    Para trabalhar direto com PKCS#12 e X.509, instale o pacote de baixo nível:

    ```package-install
    @signature-kit/certificates
    ```

    `@signature-kit/certificates` traz funções puras sobre o certificado: `toSignerIdentity(cert)` gera o mesmo `SignerIdentity` de `inspect`, `isCertificateValid(cert)` retorna um `boolean` e `daysUntilExpiry(cert)` retorna um `number`. Para bytes DER, `parseX509(der)` retorna um `Effect` com um `X509Info`.

    ```ts title="validity.ts"
    import { toSignerIdentity, isCertificateValid, daysUntilExpiry } from "@signature-kit/certificates"
    import { signatures } from "@signature-kit/signatures"
    import { Effect } from "effect"

    // forneça o mesmo a1SignaturesLayer({ pfx, password }) do primeiro passo
    export const checkValidity = Effect.gen(function* () {
      const cert = yield* signatures.certificate()

      const identity = toSignerIdentity(cert)   // mesmo formato de inspect()

      const valid = isCertificateValid(cert)    // boolean
      const days = daysUntilExpiry(cert)        // number

      if (!valid) {
        yield* Effect.logWarning("certificate out of validity")
      } else if (days < 30) {
        yield* Effect.logWarning(`certificate expires in ${days} day(s)`)
      }
    }).pipe(Effect.provide(layer))
    ```

    <Callout type="info">
      CPF e CNPJ são lidos do subject e do SubjectAltName, incluindo os OIDs ICP-Brasil `2.16.76.1.3.1` (e-CPF) e
      `2.16.76.1.3.3` (e-CNPJ). `extractBrazilianFields` faz essa leitura; o resultado já chega em `cert.brazilian` e
      em `identity.document`.
    </Callout>
  </Step>
</Steps>

## Validade com o relógio do Effect

`inspectCertificateValidity` retorna o estado (`notYetValid`, `valid` ou `expired`), o instante da avaliação, os milissegundos restantes e os dias inteiros até a expiração. Os limites inicial e final contam como válidos. Datas inválidas ou um início posterior ao fim falham com `signature-kit.INVALID_INPUT`. O limiar para alertar sobre a expiração fica com a aplicação.

A função lê o `Clock` do Effect, então dá para testá-la com `TestClock`. `parseCertificate` usa o mesmo relógio para calcular `isValid`. Confiança na cadeia e revogação são verificações à parte.

```ts title="validity-inspection.ts"
import { inspectCertificateValidity } from "@signature-kit/certificates"

declare const notBefore: Date
declare const notAfter: Date

const inspection = inspectCertificateValidity({ notBefore, notAfter })
```

## Erros mais comuns

Toda falha de leitura é um `SignatureKitError` no canal de erro:

- [`signature-kit.EMPTY_FILE`](/docs/signing/errors#error-catalog): o arquivo está vazio.
- [`signature-kit.INVALID_FORMAT`](/docs/signing/errors#error-catalog): os bytes não parecem um PKCS#12.
- [`signature-kit.WRONG_PASSWORD`](/docs/signing/errors#error-catalog): a senha do certificado está errada.
- [`signature-kit.NO_CERTIFICATE`](/docs/signing/errors#error-catalog): o arquivo não contém um certificado.
- [`signature-kit.NO_PRIVATE_KEY`](/docs/signing/errors#error-catalog): o arquivo não contém a chave privada.
- [`signature-kit.X509_PARSE_FAILED`](/docs/signing/errors#error-catalog): o certificado X.509 não pôde ser lido.
- [`signature-kit.CORRUPTED_FILE`](/docs/signing/errors#error-catalog): o arquivo está corrompido ou não é um PKCS#12 válido.
