---
title: Hooks React de assinatura
description: "Carregue o certificado, assine PDFs em sequência e acompanhe o progresso com os hooks de @signature-kit/react, mantendo os erros tipados."
---

`@signature-kit/react` expõe hooks headless para assinar com certificado A1 no navegador. O pacote não inclui armazenamento, fetch/tRPC, toasts, modais, `react-pdf` nem componentes de UI.

Para uma UI pronta, instale o componente do registry e edite os arquivos copiados para a sua aplicação.

```bash title="Instalar o diálogo de assinatura direta"
npx shadcn@latest add https://signaturekit.dev/r/signature-dialog.json
```

Para uma UI própria, use os hooks diretamente.

## Estado do certificado

```tsx title="certificate-form.tsx"
import { useA1Certificate } from "@signature-kit/react/a1"

export function CertificateForm() {
  const certificate = useA1Certificate()

  return (
    <form
      onSubmit={async (event) => {
        event.preventDefault()
        const form = new FormData(event.currentTarget)
        const file = form.get("certificate")
        const password = form.get("password")
        if (file === null || typeof file === "string" || typeof password !== "string") return
        await certificate.load(new Uint8Array(await file.arrayBuffer()), password)
      }}
    >
      <input name="certificate" type="file" accept=".pfx,.p12" />
      <input name="password" type="password" />
      <button type="submit" disabled={certificate.status === "loading"}>Carregar</button>
      {certificate.profile ? <p>{certificate.profile.subject}</p> : null}
      {certificate.error ? <p>{certificate.error.code}</p> : null}
    </form>
  )
}
```

`load(pfx, password)` envolve a senha com `Redacted.make` assim que a recebe e abre o certificado em uma sessão de Web Worker. O store do hook guarda só `status`, `profile` e `error`. O pacote não persiste nada: armazenamento criptografado e política de retenção da senha ficam com a sua aplicação.

## Assinatura sequencial

```tsx title="sign-documents.tsx"
import { useA1Signer } from "@signature-kit/react/a1"

export function SignDocuments({ pfx, pdf }: { pfx: Uint8Array; pdf: Uint8Array }) {
  const signer = useA1Signer()

  return (
    <button
      type="button"
      disabled={signer.busy}
      onClick={async () => {
        await signer.sign({
          documents: [
            {
              id: "contract",
              name: "contract.pdf",
              pdf,
              anchors: {
                matchers: [{ text: "{{signature}}" }],
                stampSize: { width: 180, height: 54 },
              },
            },
          ],
          credentials: { pfx, password: "changeit" },
          signing: { policy: "pades-icp-brasil", reason: "Assinado com SignatureKit" },
          stamp: {
            badge: {
              header: { text: "ASSINADO DIGITALMENTE" },
              rows: [[{ label: "Signatário", value: "Usuário atual" }]],
              footer: [{ text: "ICP-Brasil" }, { text: "SignatureKit" }],
            },
            rubric: { initials: "UA" },
          },
        })
      }}
    >
      Assinar {signer.rows.length} documento(s)
    </button>
  )
}
```

Se você omitir `credentials`, o hook usa o certificado já carregado por `useA1Certificate`.

Cada linha passa por `pending → signing → signed | failed`. Os documentos são assinados um de cada vez, e a linha que falha guarda o erro tipado original (`PdfError`, `CmsError` ou `SignatureKitError`). Com ele, a sua aplicação chama `errorMessage(...)` de `@signature-kit/i18n` com o locale e os catálogos que quiser.

## Object URLs de PDF

```tsx title="signed-preview.tsx"
import { usePdfObjectUrl } from "@signature-kit/react/browser-pdf"

export function SignedPreview({ bytes }: { bytes: Uint8Array | null }) {
  const url = usePdfObjectUrl(bytes)
  return url ? <a href={url} download="signed.pdf">Baixar PDF assinado</a> : null
}
```

O hook cria o object URL e o revoga no cleanup de um effect, porque esse recurso do navegador precisa ser liberado explicitamente.
