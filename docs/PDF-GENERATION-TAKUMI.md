# PDF generation: react-pdf → takumi-pdf

Licitei builds printable PDFs with `@react-pdf/renderer` in the legacy app. New SignatureKit registry guidance and the pdf-core regression corpus use [`takumi-pdf`](https://www.npmjs.com/package/takumi-pdf) **0.20.0** (Chromium layout engine, vector PDF, subset fonts, tagged PDF by default). Parsing, anchor search, and signing stay on `@signature-kit/pdf-core` / `@signature-kit/pdf`.

## Runtime

| Environment | Entry | Wasm | Notes |
| --- | --- | --- | --- |
| Bun | `takumi-pdf` → `bundlers/bun.mjs` | bundled `takumi_pdf_wasm_bg.wasm` | `initSync` optional for cold starts in benches |
| Node ≥20.19 | `bundlers/node.mjs` | same wasm | no native napi binding in 0.20.0 tarballs |
| Browser / Vite | `bundlers/vite.mjs` / `browser.mjs` | lazy wasm URL | explicit font bytes required |
| Docs (FumaPress) | client islands only | wasm fetched at runtime | never render PDFs during SSG |

`render(jsx, options)` returns `Promise<Uint8Array>`. Reuse one warm wasm init when batching documents.

## SignatureKit anchors

Registry item `pdf-signature-anchor` ships invisible takumi HTML markers:

- `PdfSignatureAnchor` — default token `{{signature}}` (text matcher)
- `PdfSignatureLinkAnchor` — default `https://signature.invalid/anchor` (link matcher)

The pdf-core corpus fixture `takumi-declaration.pdf` is generated by `shared/pdf-core/scripts/generate-corpus.ts` and exercises the invisible text token `[[licitei-assinatura]]` plus Portuguese body copy, Liberation TTF, paginated footers, and an `https://` link anchor. takumi-pdf only emits `http(s)` link annotations and drops custom URI schemes, so link anchors use `https://signature.invalid/anchor` (reserved `.invalid` TLD).

## Benchmark

`shared/pdf-core/bench/generate.bench.ts` compares react-pdf and takumi-pdf warm render times for a multi-page Portuguese declaration. Results land in `shared/pdf-core/bench/results/generate-latest.json` (gitignored).

## Docs registry decision

`@react-pdf/renderer` was removed from `apps/docs` dependencies. Preview still uses `react-pdf` (pdf.js) via `signature-pdf-viewer`; generation examples use takumi-pdf. react-pdf remains a **devDependency** of `@signature-kit/pdf-core` for the `react-pdf-declaration.pdf` corpus fixture and generation benchmarks only.
