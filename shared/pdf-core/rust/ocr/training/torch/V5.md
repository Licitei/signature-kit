# Experimental OCR v5

V5 starts from random weights and learns line transcription with CTC. The
runtime accepts an external OCR5 table under the `ctc-v5` feature. The
published OCR wasm continues to use the glyph recognizer.

The stem reads grayscale patches at horizontal stride four. A grouped
three-tap convolution preserves fine character detail. A second path packs
multiple fine frames into one frame with 384 channels, applies dilated
depthwise and pointwise convolutions, and projects back into position-specific
fine features. Its fine CTC head sees both the local and context features.

| Table architecture | Frames per context cell | Context input/output channels per fine frame | Dilations | Trainable parameters |
|---|---:|---:|---|---:|
| 1 | 8 | 64 | 1, 2, 4, 8 | 1,015,683 |
| 2 | 16 | 64 | 1, 2, 4 | 1,260,035 |
| 3 | 32 | 32 | 1, 3 | 1,110,659 |

The same normalization runs on each Python training or evaluation crop
and each Rust line probe or page crop. A sampled paper tone supplies a
foreground threshold. The line projection chooses a small integer shear.
The corrected ink hull is resized to 26 rows, with three rows and columns
of padding per side. Each normalized pixel retains seven bits of ink
intensity. For pages, segmentation still uses the cleaned binary image.
The recognizer samples the original grayscale raster through the inverse
page transform and applies the line normalization to those pixels.

## Prepare the corpus

Use the [v4 installation instructions](README.md#install) for CPU PyTorch.
All corpus files are read-only. Run the following from the workspace root.

```sh
mkdir -p .cache/t shared/pdf-core/.cache/v5
export TMPDIR="$PWD/.cache/t"
r=/home/yorizel/.local/bin/resource-run
out="$PWD/shared/pdf-core/.cache/v5"
rust="$PWD/shared/pdf-core/rust"
tools="$rust/ocr/training"
torch="$tools/torch"
bench="$PWD/shared/pdf-core/bench/ocr"
corpus=/home/yorizel/Documents/bench-parsers
py="$PWD/shared/pdf-core/.cache/venv/bin/python"

"$r" --cpu 2 --mem 3G bun "$tools/split-audit.mjs" "$corpus" "$out/exclude.txt"
seq 0 5 | "$r" --cpu 6 --mem 6G xargs -r -P 6 -I INDEX \
  bun "$bench/generate-dataset.ts" "$corpus" --labels poppler \
  --mode training-shards --split train --preset clean --dpi 150 --seed d3 \
  --partition INDEX/6 --exclude-training "$out/exclude.txt" --output "$out/corpus"
find "$out/corpus/train" -maxdepth 1 -type f -name '*.ocrl' | sort > "$out/fit.txt"
```

The split audit excludes byte-identical aliases of validation, test, and
scanned PDFs. The standard corpus generator renders and transcribes
train-split PDF pages through Poppler. It writes each uncapped line as a
gray8 crop with padding. Training samples the measured scan profiles on
the fly through the Rust degradation worker, including the in-house JPEG
encoder and decoder. It starts with clean crops and reaches the full
profile mix at epoch four. Assign a fresh output directory when changing
the source archive or split policy.

### Generate the rare-character supplement

The supplement takes sentences from the training roster. QPDF extracts
embedded TrueType streams from training PDFs. The generator checks each
font cmap and glyph coverage, then writes synthetic PDF sheets using
those same font programs. The PDF wasm emits the glyph display list and
the OCR wasm rasterizes it. The writer retains the source PDF path and font
SHA-256 in its log.

```sh
"$r" --cpu 4 --mem 8G bun run build
"$r" --cpu 2 --mem 4G bun "$tools/rare.mjs" \
  shared/pdf-core/dist/pdf-core.wasm shared/pdf-core/dist/pdf-core-ocr.wasm \
  "$corpus" "$out/fit.txt" "$out/exclude.txt" "$out/rare" 7000
```

## Fit and resume

Use the 186 reviewed real development crops and a separate calibrated
synthetic validation split. Generate synthetic validation with
`--mode lines --split val --preset calibrated --dpi 150 --seed d3`.
When a JPEG variant exists, decode it to 8-bit grayscale PGM before
validation and preserve its original dimensions. The real test split and
the synthetic test splits are held for final evaluation.

```sh
"$r" --cpu 2 --mem 4G python3 "$bench/real_lines.py" regenerate \
  "$corpus/editais-extra/digitalizados" "$out/real-lines"
"$r" --cpu 2 --mem 4G bun "$bench/generate-dataset.ts" "$corpus" --labels poppler \
  --mode lines --split val --max-docs 4 --max-pages 2 --preset calibrated \
  --dpi 150 --seed d3 --output "$out/val"
for jpg in "$out"/val/val/*.jpg; do
  decoded="${jpg%.jpg}.decoded.pgm"
  "$r" --cpu 1 --mem 3G magick "$jpg" -colorspace Gray -depth 8 "$decoded"
  mv "$decoded" "${jpg%.jpg}.pgm"
done
```

```sh
(
  cd "$rust"
  "$r" --cpu 4 --mem 6G cargo build --release -p signature-kit-pdf-core-ocr \
    --features ctc-v5,ctc-v3,synth --bins
)

"$r" --cpu 12 --mem 16G "$py" -u "$torch/train.py" \
  --architecture 3 --shards "$out/fit.txt" \
  --supplement "$out/rare/shards.txt" --supplement-fraction 0.0625 \
  --scan-binary "$rust/target/release/pdf-core-ocr-synth" \
  --real-dev "$out/real-lines/dev" --synthetic-val "$out/val/val" \
  --output "$out/fit-3" --epochs 8 --qat 2 --batch-size 32
```

Omit `--steps` to visit each eligible primary record within one epoch.
A fixed step budget traverses a deterministic shuffled roster across
epochs. The supplement has its own deterministic shuffled rotation.
Repeat the same fitting command with `--resume` for an interrupted run.
`--initial-run` can start a continuation with a different training roster
or schedule, starts with the full scan-profile mix, and records the
parent table hash in its data digest.
The data digest includes both rosters and the measured scan profile and
binary when used. The selection score averages real development and
synthetic validation int8 CER. Keep checkpoints, corpus data, and logs in
the ignored cache.

## Runtime and evaluation

`PreparedPage::recognize_sequence_with_gray(table, gray)` uses the same
source raster that prepared the page. The native
`pdf-core-ocr IMAGE --ctc-model TABLE` and the
`pdf_core_ocr_ctc_probe` wasm export accept OCR5 tables. The line
fixtures still use the `pdf_core_ocr_v4_line_probe` export and
`pdf-core-ocr-v4` executable for both formats.

The OCR5 header follows the OCR4 layout. It starts with `OCR5`, a u16
version of 1, a u16 architecture ID, a 32-byte training SHA-256, a
20-byte Git commit, a u64 seed, and a u16 class count. Ascending Unicode
u32 labels follow, with CTC blank first. The row order is stem, local
convolution, context downsampling, alternating depthwise and pointwise
rows, context expansion, and CTC head. Each row stores its i16 bias, u8
right shift, and signed int8 weights with one scale per output channel.
The v4 fixed-point units and rounding apply to v5.

Use the [v4 benchmark commands](README.md#check-and-benchmark) with the
`ctc-v5` feature and the selected OCR5 table. The fixture evaluator
accepts a PGM directory as well as an OCRL or OCRT archive. It compares
128 normalized pixel buffers and integer logit matrices across Python,
native Rust, and scalar and SIMD wasm. The native line evaluator
reports CER and WER before and after normalization and word multiset
F1. When building the probe with `ctc-beam`, add `--beam` to evaluate
the experimental CTC beam and Portuguese character bigram on the
development crops.
